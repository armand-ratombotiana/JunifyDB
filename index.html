Design Principles

Five Unwavering
Engineering Axioms

These are not marketing claims ΓÇö they are architectural constraints enforced in every code path, from the storage engine to the framework starters.

≡ƒÅù∩╕ÅΓæá

Embedded-First, Always

A database instance starts in a single method call and lives entirely within your JVM process. No ports, no sockets, no child processes, no OS services. The lifecycle of the database is the lifecycle of your application.

try (var db = JunifyDB.inMemory()) {
// ... your whole app
} // closes cleanly Γ£ô
ΓÜÖ∩╕ÅΓæí

Zero Configuration by Default

JunifyDB.inMemory() yields a fully operational database with zero config files, zero env vars, zero JVM flags. Every option has a production-safe default. Persistence is one additional line when you need it.

JunifyDB.embed()
.storageEngine(B_TREE)
.persistTo("data/")
.buildConfig()
ΓÜíΓæó

Dual-Engine: NoSQL + ANSI SQL

The same data is accessible via the fluent NoSQL API and a built-in ANSI SQL engine simultaneously. Both share the same storage substrate. Switch paradigms mid-query. Mix freely.

db.sql("SELECT * FROM users")
db.from(User.class).where(...)
≡ƒôÉΓæú

Tri-Standard Annotations

JunifyDB reads Eclipse JNoSQL, Jakarta Persistence, and Hibernate annotations transparently at runtime with zero additional classpath dependencies. Migrate standards without touching your domain model.

@Entity @Table(name="users")
@Column(name="email")
@jakarta.nosql.Column("em")
≡ƒôíΓæñ

Observable by Design

Every mutation emits a lifecycle event. Every operation is counted. Every anomaly surfaces. Built-in event bus, atomic metrics counters, Change Data Capture, and tamper-evident audit trail.

db.events().on(AFTER_INSERT, e ->
log.info("inserted: {}", e.id()));

Pluggable Storage Substrates

The query, collection, and transactional layers are fully decoupled from physical storage via the StorageEngine SPI. Switch from RAM to B-Tree to LSM-Tree with a single enum change.

.storageEngine(IN_MEMORY)
.storageEngine(B_TREE)
.storageEngine(LSM_TREE)

Storage Substrate

Four Engines, One API

Switch storage strategies with a single enum. The collection, query, and transaction API is identical across all four engines. No code changes required.

IN_MEMORY
Concurrent HashMap
Backed by ConcurrentHashMap. Maximum throughput, zero GC overhead. Ephemeral ΓÇö data lives with the JVM process.
Best for: Unit tests, CI pipelines, microservice sessions, feature flags.
FILE
Append-Only Log + WAL
Append-only sequential log with Write-Ahead Logging and automatic crash-recovery replay.
Best for: Simple persistence, single-writer local apps, edge devices.
B_TREE
B+ Tree Page Store
High-performance index-backed block storage. Fast random key lookups and ordered range scans.
Best for: Read-heavy workloads, sorted queries, product catalogs.
LSM_TREE
Log-Structured Merge Tree
Immutable SSTables with background compaction. Optimized for sequential write throughput.
Best for: Write-heavy workloads, time-series data, event ingestion.
